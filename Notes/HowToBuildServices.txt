GPT fixed version: 

If you want to build services, you must start by defining the data flow. Coding should always follow that flow—each function exists to receive, process, and transform data step by step into the final result.

For example:

You want to build a face recognition service:

First, the app captures an image and sends it to the backend.
At this point, the first data flow is created: Image → Backend.
→ You need a DTO (e.g., IFormFile, CaptureTime, DeviceId) to represent this data.
Next, the backend sends the image to the Python service.
→ This creates the second data flow: Backend → Python API.
→ You implement a service + interface to handle this communication.
In this step, the image is passed in a format that the Python API can process (typically multipart/form-data).
In Python (FastAPI), you process the image and return the result.
→ This creates the third data flow: Python → Backend.
→ The response is JSON: total faces, PeopleId, confidence score.
Now the backend receives this data and processes it.
→ This is the core transformation step:
Validate data
Apply business logic (known/unknown, duplicate check, etc.)
Convert into database model
Then the data is saved to the database and optionally sent to the UI (e.g., SignalR).
→ This creates the final data flows:
Backend → Database
Backend → UI
The Controller only receives the initial request and passes it into the flow.
The Service handles the main data transformation.
Finally, don’t forget to register the service in Program.
